# Actual-application audit captures

Screenshots are captured from the real browser application under controlled automation,
not generated concept images or human play sessions. Current suites run the shipping
v3.2.1 standalone HTML in memory, enabling only its existing diagnostic access guard.
Some scenes set score, cards, chapter, stock or clock deliberately to expose a tested
state; do not interpret them as proof a real player reached it.

`25-v321-sparse-opening.webp` shows five typed ordinary arrivals, the sixth earned ICE
opportunity still falling, and the empty two-slot inventory. The source PNG is exported
separately in the conversation; documentation copies use WebP to avoid bloating the ZIP.
Earlier numbered screenshots whose suites were rerun depict regression scenarios;
unchanged historical images are not independent new playtests. The matching reports in
`docs/qa/` identify exact shipping HTML hashes and final test results.
